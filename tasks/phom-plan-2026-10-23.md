# Plan Phỏm online — 23/10/2026

Theo SPEC-rules-phom.md; dùng file riêng theo convention các feature trước,
giữ nguyên tasks/plan.md và todo.md còn các công việc khác. User đã yêu cầu plan
UI/logic rồi triển khai; đã xác nhận9/10 lá, ăn/hạ/gửi và có đền; mọi mức tự nhập.

## Thứ tự phụ thuộc

1. Engine phỏm/tìm bộ và scoring thuần với test trước (3–4 files): A thấp,
   partition rời nhau/eaten constraints, scoring cấu hình. Verify Node focused.
2. Luồng game (2–3 files): deal/draw/eat/discard/lay/send/ù/deadline/forfeit,
   property test conservation52cards, tiến triển đến kết quả và zero-sum.
3. Room+worker (3 files): dispatch theo gameKind và quyết toán phỏm giữ result
   envelope. South cũ phải qua regression toàn functions.
4. RPC/HTTP (migration+handler+tests): create phỏm atomic, validate config, kind
   và config bất biến, title score đúng; play actions giữ receipt/CAS/deadline.
   Verify SQL PGlite role/CAS/replay và handler input.
5. Client contract (types+parser+tests): union PhomView, projection bounded,
   reject private fields/malformed melds. Session/realtime reuse.
6. Catalog/config UI (screen+form+tests): bật Phỏm, mọi mức có input, lỗi số,
   create đúng game và tên luật; verify targeted Jest.
7. Bàn Phỏm (table/styles/tests): ghế/public meld+discard, stock,lastcard,
   own hand dưới, action theo phase, sends target, result+bảng mức; dọc/ngang.
8. Review độc lập diff, sửa actionable findings, full Jest/functions/typecheck/
   lint/export; runtime khi khả dụng; cập nhật SPEC/docs/checklist/rollout.

## Checkpoints

- Sau2: engine có thể chơi trọn ván bằng fixture; không trùng/mất bài hay sai tiền.
- Sau4: HTTP/SQL đi trọn create→ready→actions→result→shared score, owner/member
  và retry giữ tương thích; review thay đổi có rủi ro trước ghép UI.
- Sau7: create/join/table/action UI dùng contract thật, south regression sạch.
- Cuối: reviewer độc lập và gates phù hợp; không tự deploy cloud.

## Rủi ro

Khác luật vùng miền: quy ước public popup/version. Ghép phỏm có lá ăn: exhaustive
partition trên tối đa10 lá, test ăn nhiều lá/overlap. Tính tiền: server-only,
zero-sum/từng config/đền ưu tiên rõ. Lộ bài: explicit projection+strict parser.
Game cũ: missing gameKind=south, không sửa luật/amountPerCard cũ. Schema: migration
additive, ACL service-only; deploy migration→Edge/worker→client.
